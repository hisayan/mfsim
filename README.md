# mfsim

PLATEAU 3D都市モデルの上で人流をシミュレーションし、OGC MF-JSON として記録・再生するプロジェクト。

## 目的

都市の「人の流れ」を、建物の実データに基づいて再現し、誰でも触って眺められる形で提示すること。
ハッカソンでは **京都駅前に 3,000 人が行き交う** シーンを、人型エージェントと一人称カメラで魅せるデモを目指す。

目指す体験:

- 京都駅前を 3,000 人のエージェントが往来する（方向・速度・混雑つき）
- 各エージェントは「人」として描写され、クリックでその人の視点（一人称カメラ）に切り替わる
- 流れは PLATEAU 建物属性（規模・高さ）から導かれ、seed 固定でいつでも再現できる

## アーキテクチャ

3層ハイブリッド構成（判断の非決定性を閉じ込める）:

| 層 | 担い手 | 役割 |
|---|---|---|
| シナリオ生成（将来） | クラウドLLM（Muse） | 自然言語 → 構造化シナリオJSON（OD・時間帯・イベント） |
| 移動計算（実装済み） | 決定的ルールエンジン | 経路・速度・混雑の物理計算。seed固定で再現可能 |
| 個別判断（将来） | ローカルLLM（WebLLM / Llama等） | 代表エージェントの分岐判断を抜粋実行。判断ログで再現 |

記録・再生は MF-JSON（OGC 19-045r3）。`(seed, パラメータ)` がそのまま再生キーになる。

## 現在の実装状況

実装済み:

- 京都駅前：流入型シミュレーション（開放系）。流入率/分＋列車到着パルスで
  人並みが増減する。`GET /api/flow` が軽量フロー形式で万人規模を転送
  （MF-JSON の約1/10）。seed決定的、混雑減速つき
- 横浜駅〜みなとみらい：歩行ネットワーク（15ノード・18辺、
  駅座標はPLATEAU関連データセット実測値）。PLATEAU CityGML bldg から
  1,436 棟の建物属性を集計（延床×高さ階級 → 行き先の誘致力）
- ダイクストラ経路探索＋混雑減速モデル、seed決定的なOD需要生成
- `GET /api/moving-features`：MF-JSON軌跡を生成（横浜用）。`source=sample` で旧サンプル
- `GET /api/walk-network`：歩行ネットワークGeoJSON（横浜・京都）
- 3Dビューア（navara）：再生・速度変更・スクラブ、群衆Instancing描画
  （リアル＝人型／サイバー＝発光ドット）、一人称追従カメラ、在圏・流入率HUD

未着手（次フェーズ）:

- 京都のPLATEAU建物3D Tiles（ZIP公開のみで配信URLが無いため建物なし表示中）
- 代表エージェントの意志（ローカルLLM / WebLLM）と一人称カメラの連携強化
- バス・タクシー・自動車エージェント（`AgentKind` 拡張で同枠組みに追加）
- シナリオ生成LLM

## 使い方

```bash
npm run dev    # UI: http://localhost:5173 （ポートは環境次第）
npm test       # lib の維持テスト（node標準ランナー）
npm run build  # プロダクションビルド
```

再生条件の例:

```text
GET /api/moving-features?area=yokohama-nishi&count=150&seed=mfsim-1
```

開発用サンドボックスの手順は [docs/sbx.md](docs/sbx.md) 参照。

## データソース

- 3D都市モデル・建物属性：国土交通省 [Project PLATEAU](https://www.mlit.go.jp/plateau/) 横浜市 2023（CityGML bldg LOD2、関連データセット）
  - 横浜市 2023 bldg には用途属性が無いため、誘致力は規模（footprint×高さ）で近似。再生成手順は `lib/sim/yokohama-nishi.ts` の注記参照
- 地形：[Re:Earth Terrain](https://terrain.reearth.land/)、航空写真：国土地理院タイル
